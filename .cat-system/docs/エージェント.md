# エージェント責務

Agent定義は「そのRoleが必要な判断を誰が所有するか」を表す。Stageごとの標準実行主体は`routing.json`で決まり、Script / Compiler / Validatorで確定できる場合は同名RoleのAI Agentを起動しない。

| Role | AIを起動する条件 | 書込み | 持たない権限 |
| --- | --- | --- | --- |
| orchestrator | flow/routing選択が必要 | Workflow台帳 | 全成果物の直接編集 |
| cycle-scope-divider | Issueの意味的分解 | Tasks / Works draft | 仕様決定 |
| cycle-git-manager | Git境界・統合方針が機械判定不能 | Review | read-only Git inspection、CI認定、merge/deploy |
| cat-reverser | code→意味Candidate復元 | CAT/Candidates | confirmed昇格、source変更 |
| cat-designer | 承認要求→CAT Draft | CAT/Draft | confirmed昇格、下流Artifact変更 |
| cat-reviewer | process-closure等がinconclusive | Review | 対象Artifact修正・promotion |
| cat-test-modeler | compiler設計/shadow調査のみ | 非normative調査物 | production TestModel直接編集 |
| cat-model-reviewer | model-conformanceがinconclusive | Review | TestModel修正 |
| tdd-test-generator | binding/renderer設定自体の設計時 | 設定Draft/Review | generated test直接編集 |
| tdd-reviewer | legacy/handwritten等のtest validationがinconclusive | Review | test/oracle修正 |
| tdd-checker | Red理由が機械判定不能 | Interpretation | Green/回帰実行、evidence編集 |
| tdd-implementer | current Queue itemの実装 | production source | spec/TestModel/Queue/test/evidence |
| ref-scoper | 保存意味とRefactor範囲の判断 | REF/Scopes | production変更 |
| ref-refactor | approved scopeの構造変更 | production source | spec/test/evidence |
| cat-implementation-reviewer | implementation obligationがinconclusive | Review | source/evidence変更、Greenからの代用pass |

## Reviewerの独立性

ReviewerはReviewだけを書き、対象Artifactを修正しない。confirmed promotionはReviewer権限ではなく、明示されたnormative decisionを受ける専用authority executor `cat_promote.py`の権限である。機械validatorの`failed`はReviewerへ送らずproducer/compiler改善へ戻す。`inconclusive`だけをReviewer起動条件にできる。

## 権限

各Roleの実効権限は自然言語Agent定義ではなくroutingの`permissions`を正とする。read/write/commands/authority/prohibitedをstageごとに解決する。書込みを持つAgentは`cat_flow.py handoff`が作るguard baselineの内側でのみ実行する。Validator後のconditional Reviewerは`handoff --conditional inconclusive`で独立guardを開始する。終了後のguard finishがpassedになるまで次stageへ遷移しない。標準Lifecycle配置ではguard開始時にdeepest-readyも再検査する。

## Skills

Agentは専門職責、Skillは再利用手順である。技術SkillはWorkが採用する技術に応じて選択する。静的なプロジェクト情報はプロジェクト文書へ置き、全Skillを常時読み込ませない。
